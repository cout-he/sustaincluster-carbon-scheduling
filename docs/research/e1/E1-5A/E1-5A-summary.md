# E1-5A：可验证逐拍 RL 环境总结

本轮实现初版 Gymnasium 调度模式控制环境，不训练 PPO/DQN，不报告学习算法性能，也没有实现最终任务级动态安全延迟预算。研究源码沿用原科研工作区；提交和发布只发生在独立发布副本。

## 实现与保护边界

`LocalExecutor.start()/advance()` 将原执行循环变成可暂停的同一内核，原 `run()` 也调用该内核。环境持有跨拍 pending/running/资源和同一个 IT/HVAC 模型；每次 reset 才创建新模型。原有 FIFO、EDF、Carbon-FIFO、EDF+Carbon、RiskOnly、Shadow/Full/CapOnly 的规则和版本号均未修改。`cars.py`、`cars_state.py`、`power.py`、`workload.py`、`metrics.py` 及生产代码保持原字节；没有改物理公式、15 分钟整拍资源占用、合成 deadline 或非抢占语义。

Action 0/1/2 分别调用现有 EDF、EDF+Carbon、RiskOnly。一次 action 决定一拍全部候选的模式，全部尚未开始的任务仍参与 EDF 排序和同一容量准入/回填。新增 40 维在线 Observation 的逐项单位、归一化、空队列处理，以及 Reward 和终止契约见 [接口定义](E1-5A-rl-interface.md)。历史压力在模式切换时连续观察，状态中没有未来真实 CI、任务到达或测试分布拟合结果。

奖励记录真实本拍碳排放、pending task-minutes、首次已发生违约，并在截断时计入所有已到达 unfinished 任务及其剩余资源工作量，包含 right-censored。未到达任务不计罚；到达窗口尚未结束且已到达前缀完成时仍是 truncated，不能声明整个 cohort 排空。非零终端负债不能证明任意权重下均不会出现 reward exploitation；正式评价继续要求有限任务集、真实 Drain、公共终点及空闲积分。

## 历史数值验证

使用未修改的 E1-3/E1-4A 完整封存输入和来源清单。源码修改前已捕获六策略微型黄金结果；修改后 batch 和 stepwise 全结构相等。正式验证源码清单包含 155 个 Python 文件，SHA256：

`2df222b9ea7bfbc1520ff70a02dbe7414940ff0d07167e64f8e77217cca7c18e`

在 1.5×/2.0× 两档分别重跑四个批量控制和三个固定 action，共 14 次。公共观察终点均为 `2023-07-03T13:45:00Z`，227 拍、56.75 小时；同档全部完成且 CPU/GPU/MEM 资源小时相等。完整账本、调度事件、逐拍资源/功率/电能/碳排放和汇总 **14/14 精确数值一致**。

| 负载 | 完成任务 | 固定 Action0 违约 / kgCO2e | 固定 Action1 违约 / kgCO2e | 固定 Action2 违约 / kgCO2e |
|---|---:|---:|---:|---:|
| 1.5× | 14,914 | 5 / 16,463.054484 | 212 / 16,319.346405 | 94 / 16,278.946405 |
| 2.0× | 19,886 | 517 / 20,182.946093 | 1,509 / 19,962.882346 | 795 / 19,887.088879 |

这些是历史结果的一致性复现，不是 RL 改善。12/14 次八个结果文件字节相同；两档 Action0 仅 `intervals.csv` 空闲尾段出现 `0` 与 `0.0` 表示差异。该文件按相同表头/行数/时间戳和逐字段 Decimal 无容差精确比较，其余七个文件仍必须 SHA256 相同。真实数值的任意小改动会被拒绝。[完整小表](numerical_equivalence.csv) 显式分开数值与字节一致性。

随机动作 seed `20261012`，215 拍，动作次数 67/73/75；同一 1.5× cohort 的 14,914 个任务全部完成，pending/running 均为0，53个已完成任务违约。排空时刻 `2023-07-03T10:45:00Z`，比固定对照公共终点早3小时，因此其86,453.173540 kWh、16,034.173604 kgCO2e **只作为 API smoke 的原始核算，不能用于优势比较**。随机轨迹未执行模型学习或参数更新。

## 数据划分

实际覆盖审计已完成，提出以下尚待下一阶段正式冻结的互不重叠 UTC 时段。每段48小时到达窗口均有192/192输入桶，CI/天气覆盖对应到达窗口及固定30天 Drain 上限；没有使用复制 CI 或尾点外推。

| 角色 | UTC 到达窗口，右端不含 | 基础任务数 | 真实环境安全终点 |
|---|---|---:|---|
| Train | May1 05:00 — May3 05:00, 2023 | 5,542 | Jun2 05:00 |
| Validation | Jul8 05:00 — Jul10 05:00, 2023 | 8,708 | Aug9 05:00 |
| Test | Sep9 05:00 — Sep11 05:00, 2023 | 6,723 | Oct11 05:00 |

新划分阈值由 `2023-04-01T00:00Z` 至 `2023-05-01T00:00Z` 的720个小时 CI 中位数固定为161.075；历史等价验证保留旧137.64999999999998，不能把晚于 Train 的旧六月校准用于新 Train。工程归一化常数预先声明，未来任何经验拟合只能使用 Train。测试候选 Sep8 的一个 workload 缺桶导致按覆盖规则顺延至 Sep9，初次失败审计保留。

原 workload 是约七周轨迹的重复扩展及2020→2023日历映射。三个窗口和已见窗口的原始任务身份无交集，但内部原始身份仍有9/263/146个重复，未去重。时间不重叠、压力种子不同均不等同真实独立 AI 业务样本。Test 仅审计数据质量，未跑策略或用其结果选模型；本轮没有生成复杂训练负载。

## 验证、发布与限制

最终测试和保护记录见 [测试证据](E1-5A-tests.md)、[验证摘要](validation-summary.json) 和 [独立审查](E1-5A-independent-review.md)。审计报告先于代码修改保存，旧来源/测试记录/归档不重写；原 main、M0 与原 Git 元数据均按文件哈希核查。

发布仅包括共享内核改动、新环境/验证驱动、测试、配置、合成黄金 fixture、精简报告和小CSV。GitHub 不包含原始任务、完整冻结输入、逐任务账本、完整日志或私有归档。历史跨版本验证需要本地封存数据、原始非内核源码字节和兼容依赖；公开副本不是自包含历史回放包。旧严格回放器未放宽，仍需旧 source snapshot 才能做旧版本严格回放。

沿用上游模型边界：每拍 IT+原定义 HVAC 积分，并非实测完整设施电力；duration/资源已知、合成 SLA、整拍占用、小时 CI 即时可获得和天气湿球代理仍是假设。RiskOnly 是启发式风险反馈而非 deadline 保证；本控制器也不具备严格安全约束证明。下一阶段须审核数据划分、奖励/截断设计、独立学习种子和正式公平核算，再决定 PPO/DQN 训练。本轮在环境验证和发布后停止。
