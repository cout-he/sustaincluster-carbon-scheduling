# E1-7A 实验A：有限Deadline排程空间

本轮找到一项真实、合法的局部改善：Train1.5× GPU高压力快照中，40候选任务的违约从11降到7；完整8,313任务的违约从153降到149。但总碳排放增加0.908028kgCO₂e。其余10个真实A2快照未降低违约。这个结果支持“存在少量局部排程空间”，尚不支持复杂资源预约或联合Carbon–SLA优势已经成立。

## 输入、约束与预注册边界

仅使用既有Train窗口：2023-05-01 05:00至05-03 05:00 UTC，1×/1.5×/2×分别5,542/8,313/11,084个冻结任务。单DC、CPU50,000/GPU1,000/MEM80,000GB、原资源倍率5、原SLA倍率1.5、15分钟网格、不可抢占、原任务duration和IT/HVAC模型均不改变。CI阈值161.075保留；实验A只优化违约数，未把CI放入目标。

在查看求解结果前，按参考EDF当前/历史特征选择CPU高压力、GPU高压力、长旧队列和低压力负对照；固定阈值与tie-break见selection-001/E1-7A-selection-manifest.json。每类每档取一个不同时间的合格快照，最多40候选。真实子集18–40任务，其中8个子集至少30任务；不足40时保留实际数量。1×的queue_long没有合格独立快照，保持空缺，未换成有利样本。

共11个真实快照×两种问题，加一个12任务合成正确性案例，合计23案例。

- **A1封闭子集**：移除全部外部任务，保留所选任务原arrival/deadline，从Train原起点允许执行。它同时移除了背景和实际历史等待，不能作为完整集群同一时段的最优值，也不是与A2只改变背景的一项消融。
- **A2固定背景条件问题**：只优化快照中的候选，其启动不得早于anchor。所有其他原任务，包括当时running和未来到达任务，保持参考EDF固定启动/释放表。完整原任务集合经同一LocalExecutor从Train起点回放。背景与候选不重计；条件EDF回填要保护背景未来固定启动承诺，因此明确是离线conditional EDF，非新在线策略。

每个任务强制执行完成，即使已经迟到仍保留全部资源和运行时长。启动在网格，真实finish=start+原Pandas duration用于SLA；资源持有到ceil_grid(finish)。同一强制区间同时参与CPU/GPU/MEM累计约束。公共真实物理观察终点均为05-03 14:00 UTC，共57小时；停止到达后Drain，提前排空后的真实空闲积分也包含在内。

## 求解状态与数值证明范围

OR-Tools9.14.6206，单线程、seed710001、每例最多120秒。目标仅为`min sum(missed)`，**没有最小等待、JCT、makespan或碳排放的次要目标**。全部23例OPTIMAL，目标值与best bound相等；求解耗时0.000484–0.074864秒，累计0.356384秒。案例总执行耗时主要来自完整物理回放，单例总耗时约0.36–23.76秒；这些计时不构成独立隔离硬件性能基准。

合成案例三维采用安全的精确binary整数格。全部22真实案例三维采用固定1e6尺度：Fraction精确ceil需求、floor容量，单项需求增加不足或等于1e-6对应资源单位，记录的容量损失为0。逐维最大误差、累计误差和系数哈希保存于oracle-solution.json。

**OPTIMAL认证只覆盖记录的保守整数资源有限子问题。** 保守量化可能排除原资源可行排程；exact binary映射也在部分math.fsum舍入边界与原操作性资源比较不同。所有结果独立按原需求、原math.fsum和原时钟验证，再通过公共执行器复放。零违约原资源可行解确证该有限问题存在零违约排程；不能把非零整数最优值直接称为原浮点问题的严格最优下界，更不能称全Train窗口理论下界。

## 唯一真实改善案例的任务与物理证据

快照为**2023-05-02 14:45 UTC，Train1.5× GPU高压力**。候选40，固定背景8,273；全部8,313原任务完成、无pending/running/删失。两方法的anchor之前135拍完整interval记录逐行一致，固定背景启动/释放一致。

任务级对照：20候选启动改变，16提前、4推后。**4个推后任务全部在anchor已无法按时完成**，分别推后15/15/30/30分钟，全部仍完成；4个被救回任务分别提前15/15/15/45分钟，没有新引入违约。其余未优化背景任务启动固定。

这更具体地揭示了一个可检查机制：在这个有限案例中，min-miss排程把部分已经不可挽回的迟到任务稍后执行，使其他仍可按时任务更早取得容量。不能把整个变化唯一归因为资源预约，更不能声称已经验证在线Conservative Backfilling的收益；迟到任务优先级处理也是应区别检验的替代解释。

三个资源占用小时在两方法中均为core-hour876,794.048014、GPU-hour19,104.877964、GB-hour932,582.957825。它们与完成量一致，减违约不来自删除任务或缩短时长。碳排放和能源变化通过真实全系统回放得到，主要能源增量来自HVAC，不能将其作为固定背景常量忽略。

oracle没有优化碳或等待，不能把随机出现的微小减碳差解释为碳最优；同一违约目标有多个时间表，JCT、最大等待和碳可能不同。上述149是一个完整Train1.5×合法时间表的**构造性可行上界**，不是全窗口最低违约数或下界；它使用离线固定背景信息，也不是在线SLA保证。
