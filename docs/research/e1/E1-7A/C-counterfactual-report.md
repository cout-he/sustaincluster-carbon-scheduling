# C：单次主动延迟的完整系统受控反事实

## 实验定义和验收

本报告基于 `C-campaign-001` 的12个预注册 Train 事件（1.5×/2×各六个），对应 selection payload SHA256 `e62b7eddcde17ee80c5eb3300b36c3a2ff4880a8899c24adc0f6fbd8b9b6c361`。不是重新选择有利事件，也不是比较两个不同在线算法轨迹。每对从同一Train起点完整重放，只有指定 `(timestamp, task_id, candidate_occurrence=1)` 的一个真实 can-fit 决策不同：立即启动，或本拍主动延迟。随后均恢复原EDF+一遍回填，不使用风险分数、未来CI或未来到达选择动作。

同状态比较包含当前候选、已到达账本、队列、running、可用资源、历史事件、已累计能碳及原IT/HVAC对象树（DC/Rack/Server/配置/数组/RNG）；两分支所有组件指纹完全相同。干预之前不读取未来FrozenWorkload/环境样本。每对实际恰好一个policy defer，其余等待按容量规则归因。任务duration、资源需求、deadline和物理公式不变。

所有1.5×分支8313任务、2×分支11084任务均完整完成，无未完成、删失和任务集合缺失。公共终点均为2023-05-03 14:00 UTC，共57小时；早排空分支沿各自持久物理实例积分真实CI/weather空闲尾段。所有对照均保持三种资源小时。两负载各自排空时间固定为11:00/11:15 UTC，即停止到达后的6.00/6.25小时；本轮单次动作没有改变排空时刻。

独立只读检查 `C-independent-review-001.json` 核对全部campaign科学文件hash、12个prefix与唯一动作、任务影响分区，及12×5个Execute控制文件与原EDF完整byte hash相同。当前初次驱动的历史控制验证条件用ISO字符串比较UTC与`+08:00`，因此自动分支未触发；这60项补充独立检查明确记录此缺口，没有将跳过称为原驱动执行通过。主代理后续更严格的时区等价检查和冻结选择回放应另行保存，不覆盖本次结果。

碳排放四个事件降低、六个增加、两个精确零变化。没有“减碳但增加违约”、减少违约或双指标恶化的样本，不能强行绘制这些不存在的案例。六个增碳事件属于碳更差、违约不变；两个零变化完整保留，不能塞入严格改善类别。

最大观测减碳是−0.255146762kg，占该1.5×公共窗口11537.214733kg的0.00221151%；最大增碳为+0.132059120kg，占2×窗口13555.204798kg的0.000974232%。这是单次局部干预，不是全局碳机会界限。各案例不组成一个联合排程，禁止将它们的差值相加宣称一个策略的总收益。

## 任务级机制证据

### 真实启动改变但总负载完全不变：合成副本互换

1.5× GPU tight 的目标是 `2023-05-02T14:45:00Z / source_row11745 / task_index4`，duration96.351667min、CPU30.024883、GPU0.027202、MEM218.056321GB。其合成copy1有完全相同arrival、deadline、duration和资源需求。Execute中原任务14:45启动、copy1在15:00启动；Defer中copy1在14:45启动、原任务15:00启动，两者都按时，其他任务不变。逐拍负载和IT/HVAC完全相同，故总能碳精确相同。

2× CPU tight同样是原任务与合成副本交换。它的z=1.339976、B30min，但既没有增量违约，也没有增量碳效应。这是任务可替代性和合成复制的结构性负对照，不能把零变化归功于风险保护，也不能用它否定所有时间转移机会。副本身份不同并不等于独立真实工作负载样本。

### 主动延迟一拍、实际等待75分钟，并传播至未来到达

1.5× long slack目标 `2023-05-01T10:00:00Z / source_row11630 / task_index3`，duration392.35min、CPU5.207457、GPU4.770748、MEM16.115053GB，deadline19:48:31.500 UTC，solo grid slack195min。Execute10:00启动、16:32:21完成；Defer发生一次policy延迟，随后四次capacity waiting，11:15才启动、17:47:21完成，仍按时。

五个干预后新到达任务的启动发生变化，分别−60、+15、+15、−15、+15min，均仍按时。当前已知其他任务无启动改变。全系统capacity waiting净增加2次，而候选自身增加4次，说明其他任务等待改变不能简单计为目标自身等待。JCT均值增加0.005413min，物理总碳降低0.255147kg。给定后续EDF，单次动作确实改变了资源竞争路径，但未产生deadline增量损失。

## IT/HVAC：当前高CI不足以判断总减碳

从原逐拍积分重新分解得到 `C-carbon-components.csv`，每拍IT/HVAC kWh乘真实CI/1000，两部分相加与完整总碳差一致（浮点重组残差最大约9.1e−13kg）。

十个非零案例的IT碳均微降，但其中六个被更大的HVAC碳增加反转为总碳增加。例如2× GPU tight：IT碳−0.000774kg，HVAC碳+0.132833kg，总计+0.132059kg；1.5× CPU tight：IT−0.000409kg，HVAC+0.029143kg，总计+0.028734kg。不能把HVAC当固定基荷，也不能以任务IT局部CI收益替代最终集群碳收益。

四个当前CI>161.075的预注册事件中，三个总碳增加、一个零变化，没有减碳；八个当前CI较低事件中四个减碳、三个增碳、一个零变化。这些类别并非按未来结果选择，但样本小且压力/slack/需求不相同，不能将这一描述性计数称为CI阈值的全窗口预测准确率。低CI干预本身不是原Carbon/RiskOnly会执行的动作，也不能将它们包装成原算法失败事件。

1.5× long slack的IT/HVAC能耗差为−0.306405/+0.166268kWh，而IT/HVAC碳差为−0.088818/−0.166329kg：HVAC总kWh略增却碳下降，说明碳变化同时涉及实际负载、环境时间与CI加权位置，不由总电能变化的符号唯一决定。

## 旧风险信号与新增时间屏幕能解释多少

原Task v1连续z覆盖0.002864至1.339976，B有15/30/45min，RiskOnly的历史缓冲有0/2拍和cold未知历史。但所有增量违约响应均为零，因此没有可估计的z–Δmiss相关、准确率或风险排序能力；本样本既不能支持有效预测，也不能证明一般无效。不训练分类器，不重新拟合权重。

支持与反例仅限条件描述：较高z=1.234586的2× history high延迟仍减碳且无额外违约；很低z=0.177177的1.5× long slack引起75分钟等待并影响五个未来任务，但未违约；两个最短slack且z最低的cold事件被B45保护，实际强制延迟仍按时，却增加碳排放。这些说明连续风险、量化缓冲、等待代价与碳收益是不同目标，不能由某一项单独代替。

预注册 `known_release_screen` 的NOW/DEFER冲突差十二个事件均为0；它没有在本样本形成增量区分信号。部分绝对冲突数非零（1.5 GPU4/4、CPU37/37；2 GPU2/2、CPU8/8），表示简化已知时间屏幕的局部容量冲突，在两个动作下相同，不等于实际新增违约预测。其余八例无符合前瞻范围的严格pending EDF前驱，checked=0。该屏幕不是真正预约，不分配其他pending，不预测未知到达，不能作为概率风险或充分可行性证明。

## 成本、缺口和解释边界

十二个pair累计记录运行时间217.413秒（包括两完整调度及诊断，不是 isolated scheduler benchmark）。源代码执行期guard通过；新增C测试23项通过，包括真实power状态、未来分叉、同拍更新、严格一次动作、资源释放、deadline、公共空闲积分。极近15分钟浮点边界的新审计按原Task Timedelta纳秒计资源小时，旧v1 history/risk的math.ceil代理未更改，其极端边界差异明确保留。

没有增加deadline违约的案例，增加违约时间线和减碳/新增违约权衡图无法诚实提供。应展示至少一个零影响副本交换和一个没有违约但发生额外容量等待的75分钟延迟案例，并保留增碳案例。不得在看到结果后重选十二事件以满足预设失效机制。

本实验结论只关于给定完整冻结环境、预注册事件和后续EDF的一次动作干预。不是所有在线控制器的普适因果效果，也不是将某一压力特征当唯一原因。本轮尚不能验证风险分数是否能识别增量deadline损失；若后续研究该问题，应预注册更大Train事件集合、审视同特征副本互换及响应稀少性，并使用独立验证，不在本轮悄悄换样本。
