# E1-2B：资源竞争下的低碳在线调度失效机理实验

本轮找到一个可复现的资源竞争问题：1.5× 和 2.0× 合成到达压力下，Carbon-Threshold 在全部完成相同任务集合后仍略减碳，但容量等待和 deadline 违约明显多于 FIFO/EDF。结果支持继续研究资源竞争风险检查，不能据此宣称 CARS 已有效或已具创新性。

## 设计与冻结边界

- 使用 E1-2A 最终归档 e1-2a-comparison-002 的 9,943 个任务及同一冻结环境，未重新选窗、校准阈值或加载新数据。到达窗口 `[2023-07-01 05:00, 2023-07-03 05:00) UTC`，15 min 步长，US-CAL-CISO，SLA multiplier1.5，资源需求倍率5（沿用原 E1 输入解释），容量50,000 CPU /1,000 GPU /80,000 GB MEM，HVAC设定22°C。
- 阈值137.65 gCO2e/kWh沿用 E1-2A不重叠历史校准结果；保留其二进制浮点表示137.64999999999998以实现逐字节历史回归。本轮没有再拟合阈值。
- 所有原任务保留一次且完全不变；按 SHA256(canonical JSON(seed20261010,task_id))、stable_id 排序选取前 `floor(N*(factor-1))` 个父任务，各复制一次。副本只改唯一task_id，保留arrival、duration、CPU/GPU/MEM、deadline及其他字段。原任务先按原序、后追加哈希排名副本；执行器原有稳定到达排序不变。各档嵌套，属于同刻确定性复制的**合成压力场景**，不是实测新增 workload。
- 离线生成器可读取冻结有限集合；策略仍仅收到已到达等待任务、当前UTC/CI和当前资源可行性，没有未来真实到达/CI输入。调度策略、任务执行顺序、物理公式、reset(seed123)/month1适配均未修改。
- 每档三策略共享相同有限任务集合；48h后无新到达，真实CI/天气持续Drain。最慢策略排空时刻是该档共同观察终点，先排空策略按同一持久物理空闲状态积分到该终点。原安全截止2023-08-02 05:00 UTC；本次所有运行在覆盖范围内排空。各档终点相同是本次观测结果，不是强制预设。

## 违约分解与代表任务

| 倍率 | 三者共有违约 | Carbon违约且FIFO/EDF均met | 上述集合中先defer再capacity任务 | FIFO/EDF违约集合异或 |
| --- | --- | --- | --- | --- |
| 1 | 0 | 0 | 0 | 0 |
| 1.25 | 0 | 0 | 0 | 0 |
| 1.5 | 2 | 399 | 20 | 43 |
| 2 | 204 | 1325 | 213 | 1440 |

“三者共有违约”仅指同一任务在三策略下都失败，不能当作所有可行调度均不可行的证明。FIFO/EDF差异表明排序本身会影响SLA；Carbon额外违约集合与主动延迟关联，不能把所有额外违约单独归因于某次延迟事件。

代表任务按事前分析规则选择：最小满足条件的负载档，再按最早主动延迟时间及task_id；未按最大损失或最漂亮轨迹选择。1.5× task_id：

到达2023-07-01 10:15 UTC，需求CPU57.803303/GPU0/MEM77.370582GB，duration129.166667min，deadline13:28:45，连续latest-start11:19:35，网格上最后可按时启动11:15。

Carbon在10:15、10:30、10:45、11:00主动defer；当时可放下该任务，CI206.6或205.35均高于固定阈值，每次连续deadline slack允许至少再等15min。11:15容量不足，可用CPU32.717311 <需求57.803303，GPU/MEM充足；未主动defer而记capacity_waited。11:30启动已超过latest-start，13:39:10完成，迟10min25s；FIFO10:15启动、EDF10:30启动，均按时完成（EDF到达拍也有一次容量等待）。

11:15的Carbon队列快照记录723个running、193个pending；其中94个正在运行的竞争任务在该任务首次defer之后才到达，其总CPU需求641.412。这些是事后任务级机制证据，没有作为策略的未来输入。当前容量可用不意味着未来deadline前仍可用；主动延期消耗了可用的启动余量，后续任务和既有任务共同形成竞争。该轨迹是配对关联证据，未执行单事件反事实干预，不宣称严格因果识别。

## 现象解释与 CARS 下一步

1.0×、1.25×没有容量等待或SLA违约；1.5×开始显著竞争，2.0×加重。Carbon相对FIFO的公共窗口减碳分别0.742%, 0.836%, 0.903%, 1.094%。本设计未显示减排百分比恶化；显示的是额外排队/SLA失效和时延代价，不能为了符合预期修改阈值、负载生成或指标。

CARS值得进入下一轮设计讨论：需要当前全等待队列资源需求、各任务剩余deadline slack/网格latest-start、非抢占running任务预计释放时刻、CPU/GPU/MEM分别的瓶颈、**截至当前**的历史到达压力估计以及当前CI。候选需要检查“等待后可预期启动余量”的风险，而不只检查duration/deadline。历史压力估计必须在线更新，不得偷看未来任务。本轮仅记录需求，未实现新策略或风险阈值。
