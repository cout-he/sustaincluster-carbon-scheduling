# E1-0 — execution mechanism audit

Baseline: `3f6ea95cb835b89ba50b0ef76d66d14b8037643e`, original HewlettPackard SustainCluster. This audit used local task/workload/environment/cluster/assignment/evaluation code, existing tests and limited mechanism probes; it did not modify production models or train RL.

Findings motivating the independent E1 implementation:

- A single DC can be configured. Global assignment, pending queues and physical stepping must be distinguished.
- Synthetic deadline is derived from arrival and duration through `sla_multiplier`; the prepared trace is not evidence of real user deadlines.
- The original load scaling and assignment paths require explicit control. Local dispatch and power evaluation ordering can create a first-step load lag or assignment-related start delay.
- EDF must reorder the complete unstarted backlog, rather than sorting only arrivals. Capacity failures remain pending; overdue tasks are not automatically cancelled.
- End-of-window unfinished tasks require explicit SLA censoring and ownership accounting.
- Top-level transfer energy is not IT+HVAC energy. Correct accounting uses the physical model's kW fields integrated over time, with explicit model boundaries.
- Reset, time alignment and input sampling must be frozen before strategy comparisons. Existing tests do not validate physical realism; the original training wrapper can pass despite a missing script.

Follow-up decisions were implemented in [E1-1A](E1-1A.md) and [E1-1B](E1-1B.md). Full machine-specific audit/probe logs remain local; this is a portable summary, not replacement raw evidence.
