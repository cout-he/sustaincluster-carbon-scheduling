# E1-1A — trusted single-DC execution foundation

The independent `experiments/e1/` implementation reuses upstream Task/resource and IT/HVAC equations. Execution order at each 15min left boundary is arrival, completion release, enqueue, admission/backfill, current-load and weather supply, physical step, energy/carbon integration. All tasks have one ledger state; CPU/GPU/MEM allocations cannot exceed capacity. Local network delay/energy is zero.

Trace rows have 12 fields. CPU=multiplier×cpu_usage/100; GPU=multiplier×gpu_wrk_util/100; MEM=multiplier×avg_mem. Arrival, duration and synthetic deadline are frozen. SLA deadline=arrival+multiplier×duration. Exact finish controls SLA, but interval-internal finishes retain resources until the next boundary. Default termination truncates; tasks with future deadlines remain censored. Frozen inputs, source snapshots and output hashes support strict replay without raw inputs.

Historical 22-step smoke: 564 arrived, 295 completed, 269 running/right-censored, zero pending or capacity waits. IT=3413.1005254048237kWh; HVAC=3789.189617984813kWh; total=7202.290143389637kWh; carbon=1777.095852067595kgCO2e. Its eight scientific files matched replay byte-for-byte. The default 24h baseline had 2506 arrived, 2385 completed and 121 censored running tasks.

Recorded acceptance at this stage: 52 tests passed (49 E1 tests plus three original tests). Historical local evidence is not included in public source; see [reproduction limits](REPRODUCIBILITY.md). Passing tests validate execution/accounting contracts, not physical calibration or true workload deadlines.
