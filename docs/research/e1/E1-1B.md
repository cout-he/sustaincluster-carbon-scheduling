# E1-1B — shared task-level scheduling baselines

Three policies reuse LocalExecutor and a common one-pass admission/backfill mechanism. EDF orders **all** unstarted tasks by deadline, arrival and stable ID at every decision. Carbon-Threshold/FIFO uses a predeclared threshold and only current CI. It may actively defer only when `CI > threshold` and `now + 15min <= deadline - duration`; equality with the threshold starts immediately, and reaching latest start disables active defer. Resource congestion can still cause deadline misses.

Wait attribution is capacity-first at each candidate turn: insufficient remaining resources means capacity waiting; a fitting task may then be policy-deferred. Both are recorded separately in task/policy events and queues. Duration/resources are immutable. Month/reset checks confirmed that explicit supplied load/weather governs the current physical path.

Historical comparison: 564 identical tasks, 22 intervals, threshold200gCO2e/kWh. FIFO/EDF each completed295; Carbon completed195 and had109pending/260running. CI stayed about244.57–249.56, always above threshold. No capacity waits occurred. Carbon's smaller window emission cannot demonstrate equal-work reduction because it completed fewer tasks and had no actual below-threshold period.
